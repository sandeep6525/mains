# FetchIQ Phase 2 Document Intelligence Report

## 1. Extraction Output Analyzed
Before generating the intelligence logic, I inspected the existing extraction output located at `output/upsc_ingestion/2026_GS1_normalized.json`.
The output schema is currently generated by `ingest_upsc_paper.py` (which internally wraps `test_question_parser.py`):
- It contains basic metadata (exam, year, paper) which was somewhat hardcoded by the orchestrator.
- It contains an array of `questions` where each object has:
  - `questionNumber`
  - `english`
  - `hindi`
  - `marks` (defaulted to `null`)
  - `wordLimit` (defaulted to `null`)

**Key Limitations Found in Existing Output:**
- **Noise:** The "Time Allowed: Three Hours..." instruction blocks are mistakenly captured as Q1 with an enormous block of text.
- **Missing Data:** Some question numbers (e.g. Q5) completely failed OCR/segmentation and are missing from the array.
- **Duplicates & Misalignments:** There are multiple "Q1" and "Q3" objects due to extraction failure splitting questions incorrectly.
- **Inline Metadata:** Marks (10/15) and Word Limits (150/250) are embedded inside the `english` and `hindi` strings, not correctly populated in the `marks` fields.

## 2. Normalization & Intelligence Design
I developed `backend/services/intelligence.js`. This is completely decoupled from the Python extraction code.
The logic receives the raw `2026_GS1_normalized.json`, and applies the following:
- **Identification:** Scans the entire raw document text using prioritized Regex heuristics to dynamically identify `Exam`, `Year`, `Paper`, `Subject`, `Marks`, `Duration`, and `Question Count`.
- **Evidence & Confidence:** Each identified field is wrapped in a payload: `{ value, confidence, evidence, method }`. If it reads "GENERAL STUDIES PAPER-I", it captures that exact string as evidence with `0.99` confidence.
- **Question Extraction & Cleaning:** It filters out the instruction blocks (checking for "Time Allowed" / "QUESTION PAPER SPECIFIC INSTRUCTIONS"), and isolates true questions.
- **Inline Parsing:** It uses Regex to pull `10`/`15` marks and `150`/`250` words out of the raw question string, populating the true `marks` and `wordLimit` fields, and cleans the text strings.
- **Validation:** 
  - Counts the unique question numbers vs the detected `Question Count` (20) and logs `MISSING QUESTION X`.
  - Finds repeating arrays and logs `DUPLICATE QUESTION NUMBER X`.
  - Checks if English or Hindi is empty and generates `MISSING TRANSLATION PAIR` warnings.

## 3. Results on Real Data (2026_GS1.pdf)
When `backend/services/intelligence.js` ran against the real provided OCR dump:
- **Identification**: Successfully extracted Year (`2026`), Paper (`GS-I`), Marks (`250`), Duration (`180`), and Question Count (`20`) purely from the text.
- **Validation Status**: `FAIL`
- **Errors Captured**:
  - `MISSING QUESTION 5` (Accurately captured the OCR skipping Q5).
  - `DUPLICATE QUESTION NUMBER 1` & `3` (Accurately captured the parser fragmenting the text).
- **Warnings Captured**:
  - Missing translation pairs for questions 2, 3, 4, 6... (because the bilingual parser failed to perfectly align the left/right columns on certain pages).
  
This proves the FetchIQ validation layer is strictly preventing bad OCR data from moving forward!

## 4. Database & Integration
- Without altering the Prisma schema destructively, the generated intelligence JSON is `JSON.stringify`-ed and saved directly to the `IngestionJob.resultJson` field.
- The status is updated to `READY_FOR_REVIEW`.
- I added the API endpoint `GET /api/fetchiq/document/:id` to retrieve this document, its job, and the intelligence payload.

## 5. UI: Admin Review Screen
I created `src/components/FetchIQ/Review.jsx`.
- Placed on the `/fetchiq/review/:id` route (dynamically injected into `src/App.jsx`).
- **Left Panel:** Displays the Extracted Metadata (Year, Paper, Exam, etc.), showing the exact confidence percentage and the quoted string evidence.
- **Right Panel:** Displays the overall Validation Status (Green PASS, Yellow REVIEW, Red FAIL) along with a list of all explicit errors (like `MISSING QUESTION 5`).
- Below the validation, it renders a scrollable list of all parsed questions, showing the isolated English text, isolated Hindi text, Marks, and Word Limit.
