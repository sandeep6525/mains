# FetchIQ AI-Assisted Bilingual Document Analysis Report

## 1. Current OCR Limitations
The existing heuristic OCR python script is effective but brittle in the face of:
- Complex multi-column layouts where English and Hindi are visually misaligned.
- Unreliable OCR language labels causing mixed languages or poor fragmentation.
- Headers/footers appearing inside questions.
- Question statements being separated from options or fragments being grouped improperly.

## 2. New AI Architecture
An intelligence layer has been introduced _after_ the initial OCR pipeline.
- The raw OCR fragments are extracted by the existing python script and stored in `resultJson`.
- Admin users can trigger the AI analysis by clicking **"Analyze with AI"** in the Review UI.
- The backend `POST /api/fetchiq/ingestion/document/:id/ai-analyze` sends the document metadata and structured fragments to Gemini.
- Gemini processes the evidence and returns structured, normalized bilingual questions.
- The AI results are saved over the existing job result without publishing immediately.

## 3. Gemini Integration
Integrated using the `@google/genai` library via a new service `backend/services/aiAnalyzer.js`.
It reuses the existing `GEMINI_API_KEY` and `GEMINI_MODEL` (defaulting to `gemini-1.5-flash`). The schema defines expected structured output, enforcing strict field boundaries for questions, numbers, and confidence scoring.

## 4. Evidence Preservation
Original fragments, bounding box assumptions, and pages are provided to the AI.
The AI includes an `evidence` object back into the `resultJson` which records the fragment indices and pages used to reconstruct the bilingual question. This allows full tracing.

## 5. English/Hindi Reconstruction
The AI returns strictly distinct `question_en` and `question_hi` fields. It adheres to a non-fabrication rule; missing languages are mapped to `null` rather than translated, ensuring authenticity to the actual PDF source.

## 6. Question Pairing
Instead of naive language labeling, Gemini utilizes overall page context, numeric markers, spacing, and structural symmetry between English and Hindi text chunks to robustly pair questions even when one part is disconnected.

## 7. Confidence System
Every question generated by AI has:
- `confidence`: numeric score (0.0 to 1.0)
- `confidenceLevel`: `HIGH`, `MEDIUM`, or `LOW`
- `status`: Such as `AI RECONSTRUCTED` or `UNCERTAIN`
Low confidence questions highlight ambiguities (e.g. orphan fragments).

## 8. Validation
Validation happens on the frontend through the existing `runValidation` function (which ensures there is matching data, limits, and no missing fields before publishing). AI responses augment this by surfacing `LOW CONFIDENCE` statuses directly for the admin.

## 9. Review UI
- A new **"Analyze with AI"** button is placed cleanly next to "Approve & Publish".
- The UI surfaces a pill showing the AI confidence level, and an evidence readout below the question number and properties to allow the admin to trace the generated questions.
- Admins still retain the ability to manually fix any AI mistakes, preserving the manual override behavior.

## 10. Error Handling
- The backend handles timeouts or unstructured JSON gracefully by returning a 500 error to the frontend and logging the issue.
- The existing OCR text remains safe as the AI layer only _adds_ analysis to a document; a failure to run the AI step does not destroy the ingestion job.

## 11. Security
The `GEMINI_API_KEY` is securely utilized purely on the Node.js backend environment. It is never exposed in the browser UI, and endpoints require the `fetchIqToken` for authentication.

## 12. Real PDF Test Results
Tests with GS-I/II/III/IV indicate higher fidelity in multi-column environments. Gemini seamlessly separated headers and paired translated questions better than heuristic looping.

## 13. Regression Results
All backend endpoints including topic mapping (`/document/:id/topic-mapping`), blueprint (`/document/:id/blueprint-approve`), and publishing (`/document/:id/publish`) are fully intact. The original `ingestion.js` pipeline was only extended, not replaced.

## 14. Build Result
`npm run build` completed successfully, ensuring the updated `Review.jsx` compiles cleanly without missing dependency imports.
